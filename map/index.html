How this figure is drawn

Nothing here is placed by hand. A script reads every page in the site's files, records the links inside the page body, and lays the result out; the clusters, the list and every count on this page come from that one pass, so the figure cannot disagree with the list under it.

Links in the shared header and footer are excluded. They appear on every page, so counting them would make every page look equally connected and hide the structure that is actually there.

Position encodes section, not link density. Each section is placed as its own region so the clusters stay separable; a layout driven by link strength puts the sections on top of one another and reads worse at this size. The link counts are carried by the mark size and by the list instead.

The figure is inline SVG, not an image, so every label is real text and survives a crawler, a screen reader and print. No diagram library is loaded: the site's only external script is the navigation, and the zoom on this page is a few lines inline.

The marks are small, and WCAG 2.5.8 asks for a target of at least 24px or sufficient spacing around it. The list above is the equivalent control: every page in the figure has a full-size link there.

FAQ

What does this figure show?

Every page on this site and every internal link between pages, grouped by the section each page belongs to. The list underneath carries the same information, with a link and an inbound count for every page.

Why is the layout grouped by section?

Because the first question a map answers is where a page sits. A layout driven by link strength alone interleaves the sections and the grouping stops being readable, so each section is placed as its own region. The trade is that position shows section, not closeness.

Does the figure need JavaScript?

No. The whole figure is inline SVG and renders with no script at all; the script on this page only adds zoom and pan. Every page in the figure is also a plain link in the list below, so the information survives if the figure is not readable at all.

Why do some labels look dimmer than others?

Marks that carry more links in this figure are labelled at full strength and the rest are dimmed, rather than removed. The names stay in the file, so a crawler, a screen reader and a print engine still get every label.
